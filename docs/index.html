The problem

Looking for a security job in Germany means checking the Bundesagentur, then LinkedIn, then StepStone, then Xing, then the remote boards. Each posting demands a reworked CV and a fresh cover letter. And after all that you still cannot tell whether you actually match the role, or which skill is the one holding you back.

How it works

Four steps, each of which you can inspect rather than trust.

Step 1

Read the CV

Upload a PDF and skills, experience, education and photo are extracted automatically. Scanned CVs go through OCR. Manual entry works too.

Step 2

Search everywhere at once

Bundesagentur für Arbeit, LinkedIn, StepStone, Xing, Indeed, Arbeitnow, Remotive, Adzuna and Jooble — queried in parallel, deduplicated, filtered by region and radius.

Step 3

Score every posting

A deterministic percentage, not a black box. Semantic similarity re-ranks the result, and each card names the skills you are missing.

Step 4

Write, then criticise

A Writer drafts the letter. A Critic scores it out of 100 and sends it back until it clears the bar. You see the score and the number of revisions.

A score you can argue with

Most job boards show a match percentage and never say how it was produced. Ours is a fixed, published weighting — the same inputs always give the same number, and you can check it by hand.

Skills 45% Role 20% Location 10% Remote 10% Seniority 10% Pay 5%

Vector embeddings then re-rank the shortlist by meaning, so a “Penetration Tester” posting still surfaces for someone whose CV says “Ethical Hacking”.

The writing pipeline

A single prompt produces a letter nobody has judged. This pipeline builds in the judgement: the Critic scores the draft against the actual posting and hands it back with specific objections until it passes.

Scout→ Matcher→ Writer⇄ Critic →Letter + score

Built on LangGraph. Every run reports its revisions and the final score, so a weak letter is visible rather than silently shipped.

What else is in it

Career pathway

Entry, mid and senior roles per domain, with the skills and certifications expected at each stage — and a live count of open positions from the official Bundesagentur API.

Skill-gap analysis

What is missing for a target role, with concrete resources: TryHackMe, HackTheBox, SANS, Coursera, MITRE ATT&CK, OWASP.

Application tracker

A kanban board from saved to offer, with every generated document kept alongside its posting.

Interview preparation

Questions generated from the posting and your own profile, not a generic list.

CareerBot

A chat assistant grounded in the product documentation, so it answers about the product instead of improvising.

Market report

Aggregates the postings found: most-demanded skills, cities, remote share, salary statistics.

Architecture

Identity is delegated, TLS is automatic, and nothing but the reverse proxy is exposed. 

                    ┌──────────────── AWS EC2 ────────────────┐
  browser ──443──►  │  Caddy  ──►  CareerAI (Node)             │
                    │    │    ──►  Keycloak  ──►  PostgreSQL   │
                    │    └── Let's Encrypt, auto-renewed       │
                    └──────────────────────────────────────────┘

  Only Caddy publishes a port. The application and Keycloak are
  reachable solely on the internal Docker network.

Delegated identity

OpenID Connect with PKCE against Keycloak, which brokers Google, GitHub and others. The app holds no password of its own, and adding a provider is configuration, not code.

Hardened containers

Read-only root filesystem, every Linux capability dropped, no-new-privileges. Separate database roles for the app and Keycloak.

Defence in depth

CSP without unsafe-inline, a static allow-list rather than a deny-list, per-route rate limits, body size caps, scrypt password hashing.

Run it yourself

No API key is required. Without one the AI features fall back to templates rather than failing.

git clone https://github.com/Calderon112/cv-skill-advisor.git
cd cv-skill-advisor
cp .env.example .env
docker compose up --build

# then open http://localhost:3000

Needs Docker, or Node.js 22.5+ with npm start. The full production stack — Keycloak, PostgreSQL and TLS — is documented in DEPLOYMENT.md.

What it does not do

Measured, not guessed. These are the limits worth knowing before relying on it.

  • Three sources are fragile. LinkedIn, StepStone and Xing are read by parsing HTML, which breaks whenever those sites change and sits awkwardly with their terms. The other six are official APIs.
  • Salaries are mostly unavailable. German postings rarely publish pay — zero of 34 ads on a live check. The app measures a band when the data allows and says plainly when it is showing an orientation figure instead.
  • CV rewriting is instructed, not verified. The model is told to use only what the source CV contains; nothing yet checks automatically that it obeyed.
  • Single instance. Sessions last 24 hours without refresh-token rotation, and PostgreSQL is not replicated. Backups run nightly.
